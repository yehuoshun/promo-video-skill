# 发布物料（写标题 / 简介 / tag 这一步）

片子渲完、`verify` 全绿，还有一道最容易掉链子的收尾：**把片子发出去**。这一步错的不是画面，
是文案——标题超字数被平台截断、tag 不够多进不了流量池、简介里写着上一版的时长、
封面拿错比例（16:9 的图传进竖屏，两边黑边）、仓库地址少打一个字母。

所以这一步也做成「唯一真相 + 可校验」：

| 文件 | 谁写 | 作用 |
|---|---|---|
| `publish.json` | 你（或 AI）写 | 三套文案的唯一真相：标题、正文、tag、视频与封面文件名、平台备注 |
| `发布物料.md` | 脚本生成 | 给人复制粘贴的视图，**不要手改** |
| `封面 16x9.png` / `封面 9x16.png` / `封面 3x4.png` | 渲染出图 | 各平台封面，比例不对会 ERROR |

```powershell
# 写完 publish.json 生成 md
python scripts-win\check_publish.py -Project . --write

# 只体检（CI / 交付前）
python scripts-win\check_publish.py -Project .
```

退出码：有 ERROR 就是 1，只有 WARN 是 0。

## 各平台硬参数（2026-11 口径，改之前先看平台上传页）

| | B站 | 抖音 | 小红书 |
|---|---|---|---|
| 标题字数上限 | 80 | 55 | 20 |
| tag / 话题数量 | 3~10（tags） | 3~5（#话题） | 5~10（#话题） |
| 视频比例 | 16:9 | 9:16 | 9:16 |
| 封面比例 | 16:9 | 9:16 | 3:4（竖屏 9:16 也吃） |
| 备注栏写什么 | 分区、转载声明 | 时长建议、循环 | 首图与配图顺序 |

标题字数不达标一律 ERROR（超了会被平台截断，钩子就废了）；短于 6 字、tag 里带 `#` 或空格只是 WARN。

## 文案里的数字别手写

三个平台各写一遍「52.8 秒」，改片子时必有一处忘了改。所以文案里用 token，生成时换成 `timing.json` 的真值：

```
@duration  52.8      @frames  3168     @fps  60
@gates     11        @scenes  5        @bpm  100
```

写死的数字也会被对账：`… 秒` / `… 帧` / `… 道闸门` / `… 个场景` / `… BPM` 五种写法逐条和 `timing.json` 比，
`52 秒` 这种取整说法算过（容差 0.6 秒），`48 秒` 直接 ERROR。

## 检查器查什么

1. **结构**：`bilibili` / `douyin` / `xiaohongshu` 三个键都在，`video` `cover` `title` `body` `tags` 都非空。
2. **平台限制**：标题字数、tag 数量、tag 里有空格或 `#`、tag 过长。
3. **事实一致**：文案里的秒数/帧数/闸门数/场景数/BPM 与 `timing.json` 一致。
4. **文件到位**：视频和封面真实存在（项目根优先，其次 `out/`）；**直接读文件头量宽高**（PNG 读 IHDR，mp4 扫 `tkhd`），
   不依赖 ffprobe，比例不符就 ERROR。
5. **地址一致**：正文里出现的 `xxx.com/yyy` 必须就是 `repo` 那串，写错一个字母会当场抓出来。
6. **md 是否过期**：`发布物料.md` 和 `publish.json` 对不上就 WARN，提示跑 `--write`。

## 常见坑

- **横屏竖屏别混用**：B站传横版（`宣传片 1080p60 横版.mp4`），抖音/小红书传竖版；竖版是重排版不是裁切，
  两边封面也要跟着换（16:9 / 9:16 / 3:4）。
- **短视频平台没有「简介」**：`body` 就是发布时那段配文，tag 单独放 `tags`（生成 md 时自动加 `#`）。
- **B站 tag 用空格分隔，不是 `#`**：所以 `hashtag: false`，别在 tag 里手动写 `#`。
- **成片不进 git**：`*.mp4` 在 `.gitignore` 里。README 想嵌播放器就传 GitHub Release 附件，
  发布时用的那份 mp4 留在项目根（`publish.json` 里写的文件名指的就是它）。
