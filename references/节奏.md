# 节奏

节奏不是感觉，是秒数。下面两张表是硬指标，写分镜时逐条对照，交付前逐条验收。

## 一、底线（每条都是「不得少于」）

| 项目 | 底线 | 为什么 |
|---|---|---|
| 重点展示镜头（产品/界面/作品高潮） | ≥ 1.3s | 短于此，观众只看到「有个东西闪了一下」 |
| 快切（蒙太奇内单张） | ≥ 0.65s | 短于此，人眼无法识别内容，等于白放 |
| 标题 + 卡片类信息场景 | ≥ 3.5s | 含 3~4 行字时，读取需要时间 |
| 网址 / CTA | ≥ 3.0s | 这是全片唯一要观众记住并行动的信息 |
| 逐个出现的元素间隔 | ≥ 0.3s | 同时出现会被读成一个整体 |
| 纯转场（无信息） | ≤ 0.6s | 转场是过门，不是内容 |
| 开场前 4 秒的画面数 | ≤ 2 个 | 第一印象来不及建立就被切走 = 什么都没说 |

## 二、密度（每条都是「必须存在」）

| 项目 | 要求 | 检查方式 |
|---|---|---|
| 痛点或核心亮点上屏 | 第 3 秒的截图里已经能看到 | 截 t=3.0s 的帧看 |
| 第一个高能点 | 5 秒内出现 | 截 t=5.0s 的帧看 |
| 新信息 | 任意连续 2 秒内至少一条 | 按 1 秒间隔抽帧，两张之间必须有变化 |
| 同一版式 | 最多连续 2 次（第 3 次必须换） | 把所有场景缩略图排一排看 |
| 单场景小节数 | ≤ 2 小节 | 数 timing.json 里该场景的 `beats` 切分 |
| 大字与旁白 | 大字最多比旁白早 1.5s，不能晚于旁白 | 对照 `voice` 与 `onscreen` 的 start |

底线防「太快」，密度防「太慢」。**两者都要，缺一不可**：只有底线，片子会拖成 PPT；只有密度，片子会闪成故障艺术。

## 三、`timing.json` 结构与规则

唯一时间真相。画面、字幕、音效、节拍都从它读。

```json
{
  "fps": 60,
  "width": 3840,
  "height": 2160,
  "duration": 52.0,
  "pace": {
    "minShot": 0.65,
    "holdShot": 1.3,
    "cardHold": 3.5,
    "ctaHold": 3.0,
    "stagger": 0.3,
    "transition": 0.6
  },
  "beats": { "bpm": 104, "offset": 0.42 },
  "scenes": [
    {
      "id": "hook-01",
      "start": 0.0,
      "end": 3.2,
      "layout": "pain-grid",
      "kind": "info",
      "onscreen": {
        "lines": ["每天手动整理 **200** 条", "改一次要 40 分钟"],
        "caption": "真实界面，不是示意图"
      },
      "voice": "你还在手动整理这些表格吗？",
      "beats": [1.15, 2.3]
    }
  ]
}
```

规则：

1. `start/end` 精确到 0.01 秒；场景之间**不许重叠，也不许留空**，首尾相接铺满 `0 → duration`。
2. `kind` 只能是 `hook` / `info` / `showcase` / `montage` / `cta` / `transition`，`check_timing.py` 按它判定时长底线。
3. `layout` 是版式名，用于检查「同版式连续不超过 2 次」。
4. `beats` 是该场景内部的信息跳变时刻（绝对秒），用于校验密度。
5. 所有时长按帧算：`Math.round(sec * fps)`，场景边界必须落在整帧上。
6. `beats.bpm/offset` 是**配乐和画面的共同约定**：`gen_music.py` 按它合成，`beatAt()` 按它呼吸，`check_audio.py` 按它验收。offset 不是 0 的时候，任何「按小节排布」的东西（和弦、鼓、音效）都要从 offset 起算，别从 0 起算——差 0.15 秒就是全程差半口气。
7. 音效也走同一个时间轴：`audio.sfx[].at` 填绝对秒数，卡在场景切点或 `beats` 上，全片 3~5 记就够，多了像在打点读机。
8. **旁白逐句，字幕同源**：`scenes[].voice` 写文案，`|` 分句；跑 `gen_vo.py` 合成后它会写好 `voiceLines`（`at/dur/sha1`）。字幕只读 `voiceLines`，`at` 由场景起点 + 0.3 秒领入，别手改。一句旁白说 2~3 秒最稳，超过 4 秒就要拆句——`check_sync.py` 会查语速（2~7 字/秒）和「有没有说到下一个场景去」。
9. **拍点要落在整帧上**：`beats.offset × fps` 必须是整数，否则任何「踩拍」的场景切点都会落在半帧，`check_timing.py` 直接报「不落在整帧上」。100 BPM @30fps 一拍 18 帧，offset 取 0.1（第 3 帧）最省事；60fps 下 0.05 的整数倍都行。
10. **屏幕上的字只写在 `onscreen`**：按槽位填（`kicker` / `lines` / `sub` / `overline` / `title` / `url` / `caption` / `tail` / `stats`），TSX 里不写字。`**字**` 是强调色，`@scenes` / `@duration` / `@frames` / `@fps` / `@gates` 是渲染时算出来的真数字。旧写法 `"onscreen": ["一段摘要"]` 已经不被渲染器接受（以前它谁也不读，改了文案画面不动），`check_timing.py` 会报出认不出的槽位或 token。

自检：

```powershell
python scripts-win/check_timing.py timing.json
python scripts-win/check_sync.py -Project .   # 有旁白时：句子不越场景、字幕不撞车
```

## 四、开头 12 秒单独检查

前 12 秒决定完播率，按 0.5 秒间隔抽帧单看一遍：

- 第 1 屏大字单独拿出来看，能否说明「这是什么」。
- 前 4 秒不超过 2 个画面。
- 推镜里每个焦点、每行字都停够 1.4 秒。
- 转场前后不黑屏，不闪错帧。

## 五、常见病

| 症状 | 病因 | 处方 |
|---|---|---|
| 「太快，来不及看画面」 | 一个镜头塞了 2 个焦点 | 拆成两个镜头，或删掉一个焦点 |
| 全程一个速度，看着累 | 全是快切，没有停顿 | 每 8~12 秒插一个 ≥2s 的定场镜头 |
| 中段走神 | 连续 6 秒没有新信息 | 加数字跳变、加切换版式、加一句新文案 |
| 结尾泄气 | CTA 一闪而过 | CTA ≥3s，且配最响的那一拍 |
| 像 PPT | 每个场景都是「标题 + 三条要点」 | 换版式密度：界面实录、全屏数字、快切蒙太奇 |
