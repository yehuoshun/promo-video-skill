# 需求问询

第 2 步专用。目标：用最少的来回，把所有会影响成片的决定一次问清，写成 `需求确认.md`。

## 问法

- **先预调研，再提问**。问题里要出现这个产品真实的名字、真实的痛点（「高潮镜头让 AI 一句话生成一份周报」而不是「高潮镜头展示什么」）。
- 一轮 5~8 题，通常两轮问完。每题第一项是推荐项，标 `（推荐）`，并在选项里带一句理由。
- **问之前先跑 `scripts-win/doctor.ps1`**：有没有 ffmpeg、能不能截 4K、有没有装 Remotion，直接决定哪些选项可以给。没条件的能力不要放进选项——给了做不到的选项，后面全在补救。
- 用户回答「你来决定」时：自己拍板，但在 `需求确认.md` 里写明决定和理由。
- 用户补充的自由文本（「不考虑授权问题」「不要我本人的声音」）原话记进 `需求确认.md`。

## 第零步：产品状态不明时先问定位

预调研发现产品**没有官方来源**（还没发布、只有灰度传闻、版本号对不上）时，第一轮之前单独问这一题——它决定后面所有素材和事实怎么用：

| id | 问题 | 选项 |
|---|---|---|
| direction | 官方还没发布，片子怎么做？ | 先备好风格、配乐、框架，发布当天填官方数据（推荐）/ 改做已发布版本 / 改做同系列已发布产品 + 结尾悬念 / 做「抢先看」，只用网友实测、逐条标出处、全片标注「未经官方确认」 |

选了「抢先看」：画面常驻「网友实测 · 未经官方确认」标记；不出现任何官方跑分、价格、功能说法；结尾用官方新闻页的真实截图说明「官方还没确认」。离交付超过半天，重新核实一次状态。

## 第一轮：定方向

| id | 问题 | 常见选项（按产品改写） |
|---|---|---|
| deliverable | 交付物 | MP4 + 同源网页版（推荐）/ 只要 MP4 / 只要网页 |
| format | 画幅与时长 | 16:9 约 45~60 秒（推荐）/ 30 秒快剪 / 70~90 秒完整版（需说明理由）/ 9:16 竖屏 / 横竖双版 |
| hook | 开场钩子（3 秒内，必须让完全不了解的人听懂第一句） | 痛点切入：目标用户最真实的 2~3 个痛点快速连击（推荐，写出具体痛点）/ 核心亮点切入：第一秒甩出最震撼的数字或作品 / 结果切入：先放成品再倒叙 |
| audience | 主受众 | 按产品列 2~4 类人群 + 建议覆盖哪类 |
| style | 风格方向 | **3~4 个针对该产品的方向，附代码样帧**（见下） |
| story | 叙事结构 | 从「问题→解法→证据→行动」「三天前/今天」「一个人/所有人」「功能巡礼」「一个作品的一生」里挑 2~3 个，每个写出旁白第一句，让用户判断外行能否听懂 |
| hero | 高潮镜头 | 最能体现产品价值的一个画面，给 2~3 个具体方案 |
| audio | 声音 | **无旁白**：纯音乐卡点 + 大字（推荐）/ 用户自己录一段真人声音 / 后接 TTS（需 key，费用与商用授权另议）。**默认给第一项**，后两项只在用户主动提及时展开 |

## 风格样帧（style 这一题必须做）

1. 挑 3~4 个**彼此差异明显**的方向，至少一个非常规的（Q 版 / 手绘 / 像素 / 黏土 / 国潮 / 档案解密），不要四个都是「深色科技感」的变体。
2. 每个方向出一张 16:9 样帧，放**真实产品名 + 一句真实文案 + 一个代表性元素**。

   本仓库没有生图能力，所以走双轨：

   - **版式与配色用代码帧定**：写一张 1920×1080 的 HTML/CSS 页面，用
     `powershell -File scripts-win/shot.ps1 -Html 样帧A.html -Out out/样帧/A.png` 截出来。
   - **画风用参考图 + 文字定**：明确告诉用户「这一轮你选的是排版和配色，画风后面单独定」。

   代码帧能画出：极简、排版、像素、霓虹、界面实录、漫画的排版语言（分格/网点/速度线/爆炸框）。画不出：角色、表情、手绘质感、线条粗细变化——需要角色的方向用 emoji / SVG 示意，并说明成片会怎么实现。
3. 用 `python scripts-win/sheet.py --dir out/样帧 --cols 2 --width 900` 拼一张对比图，嵌在回复里，再提问。
4. 用户可以混搭（「A 的配色 + C 的骨架」），记下来。
5. **代码样帧是白送的**：它就是最终场景的雏形，选中的那张可以直接改造成 Remotion 组件。

## 第二轮：定细节

| id | 问题 | 常见选项 |
|---|---|---|
| assets | 素材版权边界 | 宽松合规：自有素材 + 可商用音乐，第三方 logo 仅指代（推荐）/ 严格：无第三方 logo、CC0 音乐 / 更宽松：风险用户承担（要写进确认书） |
| showcase | 重点展示的功能/作品 | 列预调研候选，多选；问有没有必须出现、必须排除的 |
| screens | 真实截图来源 | 公开页面 + 帖子里的作品图（推荐，先做全量盘点告诉用户能拿到几张）/ 需要登录的页面：请用户在 Chrome 里登录 / 用户直接给截图或录屏 |
| music | 配乐 | 给 3~4 段 30 秒试听请用户选 / 问曲风偏好（电子 / 放克 / 励志史诗 / 轻快流行）/ 用户自带曲目 |
| cta | 网址与行动号召 | 网址写哪个、放哪（至少最高潮一次 + 片尾）、按钮文案 |
| review | 中途审阅 | 需求确认后全自动做完再交付（默认）/ 先出粗剪再精修 / 先出静帧分镜 |
| export | 导出规格 | 4K60 + 1080p60（推荐）/ 1080p60 / 4K30 |

最后一题固定：

| confirm | 以上共识是否准确？确认后开始全自动制作。 | 准确，开始制作 / 有地方要调整 |
