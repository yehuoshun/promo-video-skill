# 校验清单

校验由 AI 自主完成：发现问题 → 修 → 重新截图复核。全部通过才算交付。

## A. 自动闸门（必须 0 ERROR）

交付前只记这一条：

```powershell
scripts-win\verify.cmd .          # 目录/环境/时间轴/素材/配乐/同步/静帧/排版/成片 一次跑完，有 ERROR 就 exit 1
```

它输出一张表，失败项会带原始原因（「两张截图完全一样（差 0.00）：f060.png → f140.png」这种），照着修再跑一遍。

想单独调某一道闸门，用下面的明细命令：

```powershell
scripts-win\doctor.cmd                                     # 环境：Node/Python/Chrome/ffmpeg
scripts-win\fix-encoding.cmd -Check                        # 编码：.ps1 有 BOM、.cmd 是 CRLF（改过脚本就跑）
python scripts-win\check_timing.py timing.json             # 分镜结构、时长底线、版式重复、layout 注册
python scripts-win\check_assets.py public                  # 素材宽度、比例、重名、中文文件名、疑似放大
python scripts-win\check_audio.py public\bgm.wav --timing timing.json   # 配乐：时长、电平、拍点是否落在声明的网格上
python scripts-win\check_audio.py public\voice.wav --narration          # 旁白：句间停顿放过，只抓漏句与半段空白
python scripts-win\gen_vo.py                                            # 旁白与字幕：逐句合成并回写 voiceLines
python scripts-win\check_sync.py -Project .                             # 三对齐：字幕/旁白/画面是不是同一份时间
npm run stills                                              # 每场景 35%/85% + 首尾帧 → out\stills\
python scripts-win\check_stills.py out\stills              # 抽出来的截图之间有没有真在动
python scripts-win\check_motion.py out\stills              # 段尾有没有「前半段在动、后半段定死」（check_stills 只比 35%/85% 两帧，抓不到）
scripts-win\probe.cmd out\mock\scene.html                  # HTML 版式探针：字被裁/图变形/出画/缺字体
python scripts-win\sheet.py --dir out\stills --cols 3      # 拼审图对比图
```

`.ps1` 不要直接跑（默认执行策略会拦下它），用同名 `.cmd` 包装器；给 .ps1 传参写在 .cmd 后面即可，例如 `scripts-win\shot.cmd examples\card.html out\frame.png -Scale 1`。

**用 HTML/CSS 搭的样帧、素材页、浏览器框里的页面**，插进 Remotion 之前先过排版探针（真 Chrome 打开，查文字被裁、图片变形、出画、字体缺失）：

```powershell
scripts-win\probe.cmd examples\card.html          # 0 ERROR 才算过
scripts-win\probe.cmd examples\bad.html           # 故意做错的样本：exit 1，用来确认闸门不是摆设
```

它比肉眼看图靠谱的地方在于四个具体判定：容器 `overflow` 把文字裁掉了多少像素、`<img>` 的原始长宽比和渲染长宽比差了几个百分点、带文字的元素超出画布多少像素、整条字体栈是不是一个族名都命中不了（栈里有一个能用就算正常；全缺时 Chrome 用默认字体，你看到的不是设计时那套字）。纯装饰的渐变光斑出血不算错，只有带字的元素出血才报。

**probe 只探 HTML，探不到 Remotion 场景。** TSX 渲出来是像素，没有 DOM 可量，所以场景组件里（`src/scenes/`）的裁字、变形、出画没有任何自动闸门：`verify` 的 `[8] 排版` 在这种工程上会`SKIP`（不是通过，是没检查）。这一段只能靠第 8 阶段的静帧肉眼过——这也是为什么红线 1 要求每个场景截两帧、拼成对比图逐条看，而不是「跑完脚本就交付」。

**抽完静帧要确认「真的在动」**：

```powershell
python scripts-win\check_stills.py out\stills
```

相邻两张差值 < 0.05 判 ERROR（像素级一模一样，说明 `useCurrentFrame()` 的值没接到 style 上，或 CSS 动画在渲染器里没跑），< 0.6 判 WARN（这一段观众看不到变化）。阈值可以用 `--identical` `--static` 调。`check_video.py` 只能证明「片子是 15 秒」，证明不了「这 15 秒里有 15 个不同画面」。

**配乐要有拍子，而且拍子要落在 `timing.json` 说的位置上**：

```powershell
python scripts-win\check_audio.py public\bgm.wav --timing timing.json
```

它测四样：时长对不对（差 >0.05s 报错）、电平有没有余量（削波、峰值与 RMS 差 <6dB）、有没有 >1.0s 的无声段、拍点对不对。拍点检测只看 40~120 Hz 的底鼓频段并跳过开头 0.2 秒——宽带能量会被淡入那一下骗到。BPM 差 >2 或首拍相位差 >60ms 判 ERROR：`beatAt()` 让画面跟着拍子呼吸，音乐不在这个拍上，观众看到的就是「全程差半口气」。

没有素材也别省这一步：`gen_music.py` 按 `timing.json` 的 BPM 现场合成一条干净可商用的占位配乐，`gen_sfx.py` 生成转场用的 whoosh / click / riser。

**音画字必须对齐**（这是观众第一个看出来的错）：

```powershell
python scripts-win\check_sync.py -Project . --png out\sync.png
```

它查三组关系，任何一组坏了都是「片子看起来就是不对」，而别的闸门查不到：

- **音频↔字幕**：每句旁白都有 wav、wav 实际长度等于 `voiceLines[].dur`、文本指纹 `sha1` 对得上（改了字幕忘了重新合成，这里才会暴露）、语速在 2~7 字/秒之间。
- **字幕↔画面**：每句话完整落在自己那个场景内（说到 5.1 秒而画面 4.35 秒就切了，就是「话没说完画面就换」）、相邻字幕含进出场留白不重叠（两行字同屏，观众不知道看哪行）、字幕不跟画面大字一字不差重复。
- **音频↔画面**：每个场景切换点附近有音效、结尾 CTA 落地 0.4 秒内必须有音效、音效与切点距最近一拍不超过 90ms。

`--png` 顺手画出三条泳道（画面 / 字幕 / 声音波形 + 音效 + 拍点红线），错位一眼可见。

旁白不要手工摆时间：文案写进 `scenes[].voice`（`|` 分句），跑 `gen_vo.py` 让它逐句合成并把 `at/dur` 写回 `voiceLines`——字幕读的是同一份，永远错不开。想改文案就改 `voice` 再跑一次，别手改 `voiceLines`。


成片后：

```powershell
python scripts-win\check_video.py out\final-4k.mp4 --timing timing.json
```

它不依赖 ffmpeg，直接读 MP4 结构，查分辨率、时长、码率、音轨。`timing.json` 里配了 `audio.bgm` 却没 `soun` 轨直接判 ERROR——Remotion 的 `<Audio>` 路径写错会静默跳过，片子照常渲染，只是没声。

本机装了 ffmpeg 时可以再补一刀，看流参数与关键帧间隔：

```powershell
ffprobe -v error -show_entries stream=width,height,r_frame_rate,codec_name,duration -of default=nw=1 out\final-4k.mp4
```

渲染日志里出现 `cannot be decoded`、`Frame ... failed` 之类，哪怕渲染「成功」了也按失败处理。

## B. 审图（每轮都做，不许跳）

先出图：每个场景 35% 与 85% 处各截一帧，拼成 `out/sheet.jpg`；过渡点、爆发点、文字出齐时刻单独补截。打开对比图看，可疑的单张用原图放大。

### 文字

- [ ] 所有文字与背景对比足够：浅底上的浅色渐变字、光效中心的白字、和背景同色系的字，都要加深颜色、加描边光晕或压暗背景。
- [ ] 没有溢出、截断、意外换行；中文标题不在词中间断行（「五大核心心 / 法」要改布局或字号）。
- [ ] 叠放卡片时后面的字没有被压住。
- [ ] 数字、名称、网址全部正确，与 `调研笔记.md` 一致。
- [ ] 每条自加的定语（「纯 SVG」「七种画风」「最近才火」）都能在原帖或官方页找到原话；找不到就删掉。
- [ ] 快切蒙太奇里的文字有深色底条，不只靠文字阴影。

### 故事

- [ ] **外行复述测试**：只读 `timing.json` 的 `voice` 与 `onscreen`，按顺序写出 5 句话的「来龙去脉」。哪句接不上上一句、哪个词需要背景知识才懂，就改那句或补一张解释卡。
- [ ] 第一句旁白和第一屏大字，单独拿出来也能说明「这是什么、发生了什么」。
- [ ] 字和声音说的是同一件事：大字最多比旁白早 1.5 秒，不能晚于旁白。

### 节奏（对照 `节奏.md`）

- [ ] 重点展示 ≥1.3s、快切 ≥0.65s、信息场景 ≥3.5s、网址/CTA ≥3s。
- [ ] 网址/CTA 在最高潮出现，并停留 ≥3s。
- [ ] 第 3 秒的截图里已经有痛点或核心亮点；第 5 秒前出现第一个高能点。
- [ ] 开头 0~4 秒不超过 2 个画面；推镜里每个焦点、每行字停够 1.4s。
- [ ] 按 1 秒间隔抽帧：不存在连续 2 秒以上「画面没有新信息」的片段；纯转场 ≤0.6s。
- [ ] 把场景缩略图排一排：同一版式没有连续出现 3 次。
- [ ] 总时长在 `需求确认.md` 的范围内（默认 45~60 秒）。

### 素材

- [ ] 每个功能段落都有真实截图，全片 ≥8 张；有一段 ≥8 张真实作品的快切。
- [ ] 4K 下清晰：源图宽 ≥ 显示宽度 ×2；`check_assets.py` 报「疑似小图放大」的图换掉（自动检测只在两个信号上可靠：缩半往返误差 <0.30 或重复行列 >65%）。
- [ ] 截图没有被压扁或拉长：挑一帧看截图里的圆形头像、logo、图标是否仍是正圆，文字字形是否比原图窄。**放大、平移截图的场景重点看。** 在 HTML 里放的 `<img>` 可以直接跑 `probe.cmd` 量长宽比偏差，超过 2% 就会报。
- [ ] 截图里没有活动横幅、悬浮条、账号头像、用户名。
- [ ] 没有同一作品的相似截图重复出现。

### 画面

- [ ] 每个场景有持续微运动，没有死帧；转场前后不黑屏、不闪错帧。
- [ ] 风格与 `需求确认.md` 一致，没有滑回默认的「深色科技风」。
- [ ] 裁切位置合适，主体没被裁掉。
