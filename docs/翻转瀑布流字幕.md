# 翻转瀑布流字幕（倒鸭子 / 快闪旋转）

一句话：**画面里只有一行字，字一个一个从「白卡」里翻出来，整行被新字往左顶，走过边沿就被吃掉。**

剪映里叫「翻转大字 / 快闪旋转」，B 站叫「倒鸭子」，抖音/快手叫「快闪字幕」。叫法不同，画面是同一个东西。

> 本文的规格是照着参考片 `D:/1/Videos/11月21日(1).mp4`（2160×3840 / 60fps）逐帧量出来的，不是凭感觉写的。
> 量到的数字都写进来了，因为它们决定了像不像：白卡 121×343、字形格 222×259（1080 宽裁切坐标）。

## 一、它跟普通字幕差在哪四条

只做到其中一条都不像，四条同时成立才是这个效果：

1. **只有一行，横向流。**
   不是多行往上滚。新字从右边进来，整行被顶得往左走，走过左边沿就被裁掉——这才是「瀑布流」。
   做成多行垂直瀑布，读起来是"滚动字幕"，没有横向的推力。

2. **每个字出生是一张白色实心卡，不是字形淡入。**
   卡先在格子里立住，然后绕**底边**往前倒（`rotateX` 0°→90°，投影高度按 cos 收成 0）；
   同一个格子里，字形同时从躺平（90°）立到正对（0°）。交接完成时卡消失、字留下。
   这套交接是"翻转"的全部。少了白卡，剩下的只是一排字在缩放淡入。

3. **卡比字高，但不夸张。**
   实测卡 121×343、字形格 222×259 → 卡高 ≈ 字高的 **1.32 倍**，宽 ≈ 卡高的 **0.35**，上下各探出一截。
   早先我按"卡是两倍多高、一根细白条"做过，结果卡伸进相邻那条字幕里，读起来像画面多了根白杠。
   **这个比值别再凭感觉放大**，放大到 2 倍以上就不像了。

4. **逐字错峰 0.05~0.08 秒，颜色按词换。**
   整行看上去是一道从左往右的翻转波，不是整行一起翻。颜色按词交替（白 / 薄荷绿 `theme.accent`），一段一个色，不逐字跳。

还有一条容易漏的：**卡自己也要跟着翻变暗，但它比字亮得多**（卡 `brightness 0.7→1`、字 `brightness 0.6→1`）。
卡和字共用一条亮度曲线的话，字落定后会停在半灰——因为卡越来越侧对、字越来越正对，两者朝向是反的。
卡这一侧的暗也不能压太低：压到 0.6 以下，它在中段就变成一块灰梯形贴在行尾，读起来像脏点而不是翻转。

## 二、实现（`template/src/effects/FlipCascade.tsx`）

全部是"帧 → 值"的纯函数，没有 CSS animation、没有内部状态（Remotion 并行抓帧，CSS 时间轴不在手里，同一帧能渲出不同结果）。

每个字要算四样东西：

```ts
const q = clamp((t - at - cardHold) / flipDur);   // 本字进度
const e = easeInOutCubic(q);
const cardRot  = 90 * e;        // 卡：立着 -> 躺平
const glyphRot = 90 * (1 - e);  // 字：躺着 -> 立起来（与卡反向，共用同一个 e）
const rowYaw   = yaw * Math.sin(Math.PI * e);     // 一点偏航，纯 rotateX 太"正"
```

三条必须守的细节：

- **卡与字角度反向**。两者同转 0°→90° 的话，字会"从站着躺下去"，落定后永远看不到正脸——这是第一版最像 bug 的地方。
- **`perspective()` 写在 `transform` 里**，不靠祖先的 `perspective`。中间隔一层带 `mask` 的裁剪层时祖先透视会失效，`rotateX` 退化成 2D 压扁，画面上看就是"卡片变矮"，不像在翻。
- **字不要叠 opacity**。可见性由翻转角本身给出（侧对时是一条线），再叠透明度就变成淡入，那是另一种效果。

整行位置只累计**已出生**各字的宽度：

```ts
let pushed = 0;
for (const c of stream) {
  if (t < c.at) break;
  pushed += c.w * easeOutCubic(clamp((t - c.at) / flipDur));  // 各字按自己进度平滑贡献
}
const lineX = WIDTH * rightMargin - pushed;
```

不能用"全部字符总宽"：一行还没出生就有几千像素宽，整行会被直接推出画面，前两秒全黑。

## 三、参数怎么调

| 参数 | 默认 | 调大 / 调小会怎样 |
|---|---|---|
| `rows` | — | 词表。一个词读完，下一词从右边涌进来。词内 `**字**` 走强调色 |
| `fontSize` | 190 | 字号（1920×1080 布局坐标）。**参考片是 220 / 行高 260**，一行只容得下 5~6 个字。字小了看不出翻转，会读成一排小字在淡入 |
| `rowHeight` | 260 | 行高，必须 ≥ `fontSize × 1.15`（组件直接抛错，不静默 clamp——静默 clamp 只会在成片里变成叠字） |
| `charStagger` | 0.08 | 逐字错峰（秒）。参考片实测 0.05~0.08；设 0 = 整行一起翻 |
| `flipDur` | 0.26 | 单字翻完用时。整行翻完 = `flipDur + (字数-1) × charStagger` |
| `cardHeightRatio` | 1.32 | 卡高 / 行高。**实测值，别放大到 2 倍**（会伸进相邻字幕） |
| `cardWidthRatio` | 0.35 | 卡宽 / 卡高。卡是竖条不是方块 |
| `yaw` | -10 | 翻转中途的偏航（deg）。0 = 纯 rotateX，最"正"；-10 是参考片的斜度 |
| `depth` | 900 | 透视距离（px）。越小越冲，越大越平 |
| `anchor` | 0.58 | 字底基线所在纵坐标（0 顶 / 1 底）。**它不是行中心**：卡从基线往上立 |
| `phrasePause` | 0.16 | 词读完停多久再进下一词 |
| `rightMargin` | 0.94 | 新字停靠位置（占画面宽比例） |
| `card` | 1 | 白卡不透明度。0 = 不出卡（退化成纯字翻转） |

**多行同时用**时行距要 ≥ 行高 × 1.4：卡比行高出一截，行距按行高给会叠成一团。参考片只有一行，样板间里的 `FlipMulti` 才是三行构图。

## 五、接到产品片里

它跟 `src/effects/` 其他八个纯参数组件的分工不同（自己读 `useCurrentFrame/useVideoConfig`），用法一样：拼进场景，文案从 `timing.json` 取。

```tsx
<FlipLine
  rows={sc.onscreen?.lines ?? []}   // 文案只从 timing.json 来
  anchor={0.72}
  fontSize={150}
  rowHeight={180}
  charStagger={0.08}
  flipDur={0.26}
/>
```

三条硬约束：

1. 文案**只写** `timing.json` 的 `onscreen.lines`，别在组件里写死（红线，破坏后改文案要改两份）。
2. 一条字幕的时长用 `flipFrames` 算，别手写帧数；换词表后手写的一定漂。
3. 多行叠用时行距按 ×1.4 给（见上一节）。

## 六、验证与踩过的坑

看画面按这几条判：只有一行、字从白卡里翻出来而不是淡入 → 整行被新字往左顶（不是原地换字）→ 旧字是被边沿吃掉的，不是硬切消失 → 卡落定后不留灰色细线。

实测教训（每条都带着数字，别当建议看）：

- **4K 样板间自己也要套 zoom 容器**。`Flip4k` 直接按 3840×2160 渲染时，组件内部的布局坐标仍是 1920×1080，而 `AbsoluteFill` 已经是 2160 高 —— 锚点、底边全部按 2160 算，字幕掉到画面 **0.655~0.781**（应为 0.52），字号相对只剩一半。照 Root 的 `Video` 包一层 `zoom = width / WIDTH` 的容器后回到 **0.463~0.563**。（2026-11-22 实测）
- **4K 下别用 `useVideoConfig().height` 算锚点**：4K 靠 Root 的 `zoom` 放大，布局空间仍是 1920×1080；取成 2160 会让锚点掉到画面外，1080 样板间完全看不出来。组件里用的是 `lib/timing` 的 `HEIGHT`。
- **白卡全程实心，靠几何自己收场**：`rotateX` 到 90° 时投影高度就是 0，不需要提前淡。早先写成「倒到一半就开始淡」（`1 - (q-0.35)/0.45`），结果是中段一块 60% 的白叠在黑底上，被读成灰色梯形贴在行尾——这才是那个"脏点"。现在只在最后 15%（`1 - (q-0.85)/0.15`）收尾，纯属防边缘闪烁。
