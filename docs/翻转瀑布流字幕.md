# 翻转瀑布流字幕（倒鸭子 / 快闪旋转）

一句话：**字幕不是一条条淡入淡出，而是在一个锚点上出生、把整串旧行往上顶走的一条传送带；每行出生时绕自己的底边翻起来。**

剪映里叫「翻转大字 / 快闪旋转」，B 站叫「倒鸭子」，抖音/快手叫「快闪字幕」。叫法不同，画面是同一个东西。

## 一、它跟普通字幕差在哪三条

只做到其中一条都不像，三条同时成立才是这个效果：

1. **行是传送带上的行，不是一个个独立弹出的窗口。**
   所有行共享**同一条**上行位移曲线（`conveyor(beatsElapsed)`）。新行在锚点出生，旧行被整体顶上去一行。
   如果每行各自往上飘，相邻行的位移曲线不同，行距会在中途塌成一张叠字——这是自己实现时最常见的翻车方式。

2. **位移是阶梯，不是匀速。**
   一拍之内 `hold` 那段**完全静止**，剩下 `1 - hold` 才把整串行推上去一行。
   静止那段就是观众读字的气口；匀速滚动会变成跑马灯，「卡点感」全在静止里。
   默认 `beat 0.34s / hold 0.45`：一拍 10 帧，前 4~5 帧不动、后 5~6 帧顶上去一行。

3. **翻转绕 X 轴、原点在底边。**
   `transformOrigin: "50% 100%"` + 父级 `perspective: 1400` + `rotateX(-78deg)`：字像门板从地面立起来。
   换成 `rotateY`（绕竖轴）会变成旋转木马，没有「翻」的物理感；原点放中心会变成「压扁再弹开」，也没有。
   逐字错峰（`charStagger 0.04s`）再加一层：一行字是从左到右一个字一个字立起来的。

还有一条容易被忽略的：**明暗要跟着翻**（`filter: brightness()` 从 0.32 回到 1）。翻起来的半程背光、落定才全亮；少了它，观众看到的是「缩放 + 淡入」，不是一块门板翻过来。

## 二、实现（代码在 `template/src/effects/FlipCascade.tsx`）

全部是「帧 → 值」的纯函数，没有 CSS animation、没有内部状态：

```ts
// 拍数 -> 上行了多少行。拍内阶梯：先停 hold，再 easeInOutCubic 顶一行
export function conveyor(beatsElapsed: number, hold = 0.45): number {
  if (beatsElapsed <= 0) return 0;
  const k = Math.floor(beatsElapsed);          // 整拍：已经顶上去了 k 行
  const local = beatsElapsed - k;              // 拍内进度
  const p = clamp((local - hold) / (1 - hold)); // 静止段之后才开始推
  return k + easeInOutCubic(p);
}
```

第 i 行的位置只跟 `conveyorAt - i` 有关：

```ts
const beatsElapsed = (frame - from * fps) / (beat * fps);
const conveyorAt = conveyor(beatsElapsed, hold);   // 所有行共用，行距永远锁死
// 每行：slot = conveyorAt - bornAt（0=刚出生，1=被顶到上一格）
transform: translateY(-slot * rowHeight)
```

翻转按字符索引算延迟，所以不需要逐帧累加状态（逐帧累加会让渲染器并行抓帧算出不同结果）：

```ts
const stagger = charStagger / beat;                       // 0.04s / 0.34s = 0.117 拍
const q = clamp((beatsElapsed - bornAt - ci * stagger) / flipBeats);
rot = flip * (1 - easeOutCubic(q));                       // -78° -> 0°
filter = brightness(0.32 + 0.68 * easeOutCubic(q));       // 背光 -> 全亮
```

顶上那条渐隐用 `mask-image` 的线性渐变做（不是把旧行 `display:none` 砍掉），旧行是从画面上沿被「吃掉」的；再叠一层 `fadeFrom` 之后的整体淡出，两段叠加才不会在快出画面时突然变透明。

## 三、参数怎么调

| 参数 | 默认 | 调大 / 调小会怎样 |
|---|---|---|
| `rows` | — | 文案。行内 `**字**` 走强调色。行数 × `beat` ≈ 这段能撑多久 |
| `beat` | 0.34 | 每拍秒数。调小更急促（快闪感），调大更像口播字幕。**必须能整除配乐拍长**，否则越走越歪 |
| `hold` | 0.45 | 拍内静止占比。0.3 更冲、0.6 更稳。低于 0.25 就没有读字时间了 |
| `flip` | -78 | 起始角度。绝对值越大翻得越深；-40 左右只是「轻轻一立」，-90 是完全平躺再立起来 |
| `flipDur` | 0.26 | 翻完用时。**不要超过 `beat`**，否则上一行还在翻、下一行已经出生 |
| `charStagger` | 0.04 | 逐字错峰。设 0 = 整行一起翻（更稳、更适合长句） |
| `rowHeight` | 132 | 行距。**必须 ≥ fontSize × 1.2**，不然翻起来时上下行会撞 |
| `anchor` | 0.76 | 新行出生在哪（0 顶 / 1 底）。0.76 是下三分之一，上方留出旧行的空间 |
| `fadeFrom` | 4 | 第几行开始淡出。调小 = 同屏行数少、更新更频繁 |

样板间里两个版本（`npm run render:flip` / `render:flip-calm`）：

- **Flip**：`beat 0.34 / charStagger 0.04 / flip -78`，适合「快闪卡点」段，一行字 0.34 秒，很冲。
- **FlipCalm**：`beat 0.62 / charStagger 0 / flip -64`，整行一起翻、翻得浅，读得清，适合口播正文。

## 四、接到产品片里

`FlipCascade` 跟 `src/effects/` 里其他八个效果一样，是「给 frame 和文案就出画面」的组件，直接拼进场景：

```tsx
// src/scenes/你的场景.tsx —— 文案仍然只来自 timing.json 的 scenes[].onscreen
export const PainCascade: React.FC<{ sc: Scene }> = ({ sc }) => {
  const rows = slots(sc).lines ?? [];   // 跟别的场景一样从 onscreen 取槽位（lib/onscreen.ts 的 slots）
  return (
    <AbsoluteFill>
      <GradientMesh frame={useCurrentFrame()} fps={useVideoConfig().fps} />
      <FlipCascade rows={rows} beat={60 / timing.beats.bpm} hold={0.45} fontSize={88} />
      <FilmLook frame={useCurrentFrame()} />
    </AbsoluteFill>
  );
};
```

三条硬约束（整个模板通用，违反会渲出坏片）：

1. `beat` 跟配乐拍长对齐：`beat = 60 / bpm`（当前 `timing.json` 的 bpm 是多少就填多少），对不齐时卡点会逐渐漂移。
2. 文案**只写** `timing.json` 的 `onscreen.lines`，别在组件里写死（这条是红线，破坏后改文案要改两份）。
3. 时长留够：最后一行出完之后还要 `(fadeFrom + 1.4)` 拍才能淡干净，否则会在满屏字上硬切。样板间用 `flipLabFrames(beat, from)` 算。

```powershell
cd code\promo-video-skill\template

```

看画面时按这几条判：行距全程锁死（没有两行叠在一起）→ 每拍之间有可读的静止段 → 新行从底部立起而不是整体淡入 → 顶上旧行是被渐隐吃掉的，不是被硬切。
