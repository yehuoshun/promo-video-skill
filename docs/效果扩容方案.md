# 效果扩容方案：B 站那 20 个开源动画工具，只有 4 个该进这条管线

- **起因**：B 站《AI 做动画能有多炫？10 分钟看 20 个开源工具》（BV1vpWq6xENs，UP 洛克AI，9:56，2026-11-13）简介列了 20 个开源动画工具，逐个讲了"擅长什么、适合用在哪"。
- **要回答的问题**：这些工具里哪些能接进本项目这套 Remotion 4K 管线，接进来解决什么镜头，代价多少，哪些不能碰。
- **数据来源**：GitHub API 20 个仓库实测（stars / license / pushed_at / latest release，2026-11-14 当日）、npm registry 最新版与发布日期、各项目官方文档站。拿不到的（`raw.githubusercontent.com` TLS 失败、`docs.synfig.org` 不可达）在文中标"未证实"，没有一项是按印象填的。

---

## 0. 结论先行

1. **20 个里只值得接 4 个**：`@remotion/lottie`（图标/UI 微动效）、`Flubber`（形状 morph）、`Manim`（离线公式推导通道）、`@remotion/three`（有 3D 素材才开）。其余 16 个不接，理由分三类：与"每一帧由 `useCurrentFrame()` 算出"直接冲突、功能已被本项目的 `anim.ts`/`effects/` 覆盖、只能离线且不如 Manim 那条链路划算。
2. **真正的成本不在"装一个库"**，在给离线渲染修一条通用通道（`render-offline` + 第 11 道闸门）。这条通道一次投入约 1 人日，之后 Blender、Godot、Manim 三类外渲器都走同一个口子，素材格式、透明度、4K 尺寸、许可证四件事一次管住。
3. **不要为了"看起来炫"去放宽确定性**。`verify.cmd` 那十道闸门是这套管线真正的资产；20 个工具里有 4 个（AnimXYZ / mo.js / KUTE.js / React Spring）一接进来就会把"同帧必须同图"这条地基打掉。
4. **新能力要配预算**：新效果全片最多 2 处、每处 ≤1.5 秒，否则宣传片会退化成 demo reel——那支 B 站视频的 20 段演示是"展示工具"，我们的目标是"45 秒让人相信产品"，两种片子的节奏不通用。

## 1. 现状：这条管线凭什么是现在这样

判定能不能接，基准是下面六条（细节见 `AGENTS.md`，这里是摘要）：

| 事实 | 位置 | 对扩容的含义 |
|---|---|---|
| Remotion 与 `@remotion/*` 全部精确 pin 在 **4.0.543**，React 19 | `template/package.json` | 新装的官方包必须同版本，不能 `^` |
| 效果统一签名 `(frame, fps, opts)`，组件不自己读 `useCurrentFrame` | `template/src/effects/index.ts` | 新效果照抄这个形状就能进样板间 |
| 动效全是纯函数（`ramp`/`enter`/`spring`/`keys`），伪随机走 `rand(seed)` 不用 `Math.random()` | `template/src/lib/anim.ts`、`effects/rand.ts` | 自带时钟、逐帧累加的库一律不能进 |
| 版式注册表 `LAYOUTS` 3 个 + `Missing` 红底兜底；`check_timing.py` 直接读 `Root.tsx` 的键集合，不维护第二份清单 | `template/src/Root.tsx:16`、`scripts-win/check_timing.py:109` | 新增版式不用改闸门；但 `onscreen` 新槽位要三处同步 |
| 4K 是 `zoom` 整块放大（布局按 1920×1080 写） | `template/src/Root.tsx` | **外部素材要按 1x 显示尺寸的 2 倍渲染**，否则 4K 出片会糊 |
| 十道闸门 + `EffectsLab` 18 秒样板间（不走 timing.json） | `scripts-win/verify.ps1`、`template/src/scenes/EffectsLab.tsx` | 新效果必须先在样板间能过闸门 |

一句话：**这套东西的地基是"画面是时间的纯函数"**。扩容只有一个标准——别动地基。

## 2. 判定尺子：四问，答不上来就不接

1. **能不能只给一个 t 就得到那一帧？** 库里有没有 `seek(t)` / `Engine.update(delta)` / `f(t)` 这类外部驱动接口。
2. **第 N 帧能不能不模拟前 N-1 帧？** 渲染器并行抓帧，需要"从头积分"或"自带历史"的库会算出不确定的结果。
3. **它会不会自己抢时间？** `requestAnimationFrame` 主循环、`performance.now()`、CSS `transition/animation` 自己跑——有一个就算不合格（CSS 动画理论上可用 `animation-play-state` + `animation-delay` 同步，但等于放弃可维护性，本项目不采用）。
4. **这个镜头宣传片真的需要吗？** 第 4 问是防"20 个都接"的闸：能删掉而不影响观众理解的镜头，就不该做。

据此分四档：

| 档 | 含义 | 判定 | 本清单里的 |
|---|---|---|---|
| **A** | 有官方 `@remotion/*` 包，装完即用 | 内部已把库接到 frame 上 | Lottie、Rive、Three.js |
| **A-** | 天生纯函数，零封装 | `f(t) → 值` | Flubber |
| **B** | 有 seek 或固定步进，需自己包成 `frame → value` | 答得上第 1、2 问 | Anime.js、Matter.js、tsParticles（偏难）、Motion（未证实） |
| **C** | 独立引擎，渲成视频/图序列再嵌回 | 离线出图命令查实 | Manim、Blender、Godot、OpenToonz、Synfig、Inochi2D、Motion Canvas |
| **D** | 纯 CSS/DOM 或自带主循环且无公开 seek | 直接违反第 3 问 | AnimXYZ、mo.js、KUTE.js、React Spring |

## 4. 第一批：三件（合计约 1.5 人日）

### 4.1 Lottie：把"图标微动效"从手写变成素材

- **解决什么**：现在图标只会整体淡入淡出；UI 微交互特写（勾选、开关、加载环、箭头流转）手写 SVG 太贵。
- **怎么接**：`npm i @remotion/lottie@4.0.543 lottie-web@5.13.0`，JSON 放 `<项目>/public/lottie/*.json`，组件里 `<Lottie animationData={data} />`。
- **关键点**：`<Lottie>` 内部自己读 `useCurrentFrame`，与本项目"组件吃 frame"的约定冲突——**用 `<Sequence from={at}>` 包一层做偏移**，Sequence 会把帧号归零，约定即恢复，不用改 Lottie。
- **4K 优势**：矢量，放大 2 倍不糊，是本方案里唯一"零 4K 成本"的效果。
- **风险**：第三方 AE 模板的商用授权要跟素材一起记（见第 7 节）。

### 4.2 Flubber：形状 morph（最"显会做动画"的一招）

- **解决什么**：logo A→B、"旧流程的表格"变形为"新流程的看板"、图标切换的连续过渡。
- **怎么接**：`npm i flubber@0.4.2`，新建 `src/effects/Morph.tsx`，签名 `(frame, fps, { from, to, at, dur })`：

  ```tsx
  const interp = useMemo(() => interpolate(from, to), [from, to]); // 只建一次
  const t = ramp(frame, at, dur);                                  // 复用 anim.ts
  return <path d={interp(t)} fill={...} />;
  ```

- **关键点**：两条 path 要同坐标系、同方向；点数不同 flubber 会插值补齐；多个形状用 `interpolateAll`。渐变/描边走现有 `effects/LightSweep` 叠加即可。
- **成本**：2~3 小时，含形状预处理与锚点对齐。

### 4.3 Manim 离线通道（唯一需要动管道的一件）

- **解决什么**：公式逐行推导、坐标系/几何演示、算法流程推演——宣传片里"这东西怎么运作"的最高级的一段，Remotion 手写几乎做不出来。
- **链路**（新增 `scripts-win/render-offline.cmd` + `.ps1`）：

  ```
  项目/public/offline/<name>/frame_0000.png … frame_00NN.png
  项目/public/offline/<name>/meta.json
  ```

  `meta.json`：`{ name, source, command, fps, frames, width, height, alpha, license, generated }`——`source`/`license` 是给第 7 节闸门查的，缺了就不让过。

- **渲染侧**：`manim -qh --format=png-sequence -t scene.py Scene`。这句是查过源码的（manim 0.22.1，`manim/cli/render/render_options.py`）：
  - `--format` 的取值是 `auto/none/png/png-sequence/gif/mp4/webm/mov`，帮助原文 *"PNG renders only the last frame; **png-sequence writes every rendered frame**"*——所以要逐帧 PNG 必须写 `png-sequence`，写 `png` 只会得到最后一帧。
  - `-t` 加 `--format=mp4` 会直接抛错，`manim/_config/output.py` 原文：*"MP4 output does not support an alpha channel. Use --format=mov or --format=webm for transparent video."*
  - PNG 序列比 `.mov`/`.webm` 稳：每帧一个文件，不依赖解码器与 seek（编码坑见 `docs/windows-踩坑记录.md`）。manim 自己的帧文件名不稳定，**由 `render-offline` 统一改名为 `frame_%04d.png`**，Remotion 侧不依赖上游命名。
- **环境成本（本机实测，别低估这一步）**：`manim` 与 `ffmpeg` 在这台机器上都**没装**（`Get-Command manim` / `ffmpeg` 均为空）；`MathTex` 还要 TeX Live（Windows 上按 GB 算）。建议第一批用**不依赖 LaTeX 的几何/流程图镜头**把通道验通，公式镜头等 TeX 环境装好再上——否则 1 人日会被环境安装吃掉大半。
- **Remotion 侧**：

  ```tsx
  <Sequence from={at} durationInFrames={n}>
    <Img src={staticFile(`offline/${name}/frame_${String(frame).padStart(4, "0")}.png`)} />
  </Sequence>
  ```

- **为什么不用带 alpha 的视频**：最终交付是 h264 mp4，alpha 本来就会在导出时被压平；透明只能靠 RGBA PNG 叠在场景底图上。所以**离线素材统一 PNG 序列 + 透明通道**，不引第二套视频解码路径。
- **体量与 4K 的硬账**（决定"离线镜头只能做局部"）：
  - 1080p RGBA PNG ≈ 1.5~3 MB/帧 → 2 秒 @30fps = 60 帧 ≈ **90~180 MB**；
  - 2160p ≈ 4~8 MB/帧 → 同样 2 秒 ≈ **240~480 MB**；
  - 而 4K 是 1x 布局 zoom 2 倍，**外渲素材要按 1x 显示尺寸的 2 倍出图**：局部元素在布局里占 900×500 px，就得渲 1800×1000。
  - 结论：**离线只做局部元素，全屏镜头不许走离线**，除非 ≤1 秒且确认仓库外挂。
- **不进 git**：`public/offline/` 加进 `.gitignore`（和 `out/` 一样视为可重生成产物），否则几十上百 MB 二进制会把仓库撑爆；靠 `render-offline` 一条命令重建。

## 6. 不接清单（写清为什么，避免下次重议）

| 工具 | 一句话理由 |
|---|---|
| AnimXYZ | 纯 CSS transition，违反"每帧由 frame 算出"，无补救；能力被 `enter()` 覆盖 |
| mo.js | 仅私有 `setProgress`，release 停 3 年，CoffeeScript 技术栈 |
| KUTE.js | 无文档化 seek、生态弱、与 `effects/` 重叠 |
| React Spring | 同功能已有纯函数弹簧；引入即两套口径 |
| Motion（Framer Motion） | 无 seek、官方 issue #399 仍未解决；布局/手势动画在宣传片里用不上 |
| Matter.js | 要"预积分存表"，本质离线；掉落堆叠用纯函数画更可控 |
| tsParticles | 自带 rAF，无 seek，只能改内部或自绘——那就不是它了 |
| Motion Canvas / Inochi2D / OpenToonz / Synfig | 只能离线，且 CLI 未查实；Manim 通道覆盖同类需求，需要时再按同一条链路补 |
| Godot | 同上（透明只有 PNG 序列），除非要做游戏化小剧场 |
| Remotion Skills | 不是渲染库，不进画面 |

## 8. 效果预算（防片子变 demo reel）

- 新效果**全片 ≤2 处，单处 ≤1.5 秒**；同一段不许叠两个炫技效果。
- 判断法：把这段效果删掉，观众是否仍看得懂？看得懂就删。
- 位置限制：Morph 只用在"转场"（旧→新），不用在"装饰"；Lottie 只用在"讲 UI"的那 1~2 个镜头；Manim 只用在"讲原理"的那一段。
- 一支 45~60 秒的片子：0~1 个 Manim 段 + 1~2 处 Lottie/morph 即可，剩下的靠 `anim.ts` 的节奏。
