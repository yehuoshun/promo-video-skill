# 效果扩容方案：B 站那 20 个开源动画工具，只有 4 个该进这条管线

- **起因**：B 站《AI 做动画能有多炫？10 分钟看 20 个开源工具》（BV1vpWq6xENs，UP 洛克AI，9:56，2026-11-13）简介列了 20 个开源动画工具，逐个讲了"擅长什么、适合用在哪"。
- **要回答的问题**：这些工具里哪些能接进本项目这套 Remotion 4K 管线，接进来解决什么镜头，代价多少，哪些不能碰。
- **数据来源**：GitHub API 20 个仓库实测（stars / license / pushed_at / latest release，2026-11-14 当日）、npm registry 最新版与发布日期、各项目官方文档站。拿不到的（`raw.githubusercontent.com` TLS 失败、`docs.synfig.org` 不可达）在文中标"未证实"，没有一项是按印象填的。

---

## 0. 结论先行

1. **20 个里只值得接 6 个，分两批**：第一批 `@remotion/lottie`（图标/UI 微动效）、`Flubber`（形状 morph）、`Manim`（离线公式推导通道）；第二批 `@remotion/three`（有 3D 素材才开）、`@remotion/rive`（有 Rive 素材才开）、`Anime.js`（先验通 seek 封装再接）。其余 14 个不接，理由分三类：与"每一帧由 `useCurrentFrame()` 算出"直接冲突、功能已被本项目的 `anim.ts`/`effects/` 覆盖、只能离线且不如 Manim 那条链路划算。
2. **真正的成本不在"装一个库"**，在给离线渲染修一条通用通道（`render-offline` + 第 11 道闸门）。这条通道一次投入约 1 人日，之后 Blender、Godot、Manim 三类外渲器都走同一个口子，素材格式、透明度、4K 尺寸、许可证四件事一次管住。
3. **不要为了"看起来炫"去放宽确定性**。`verify.cmd` 那十一道闸门是这套管线真正的资产；20 个工具里有 4 个（AnimXYZ / mo.js / KUTE.js / React Spring）一接进来就会把"同帧必须同图"这条地基打掉。
4. **新能力要配预算**：新效果全片最多 2 处、每处 ≤1.5 秒，否则宣传片会退化成 demo reel——那支 B 站视频的 20 段演示是"展示工具"，我们的目标是"45 秒让人相信产品"，两种片子的节奏不通用。

## 1. 现状：这条管线凭什么是现在这样

判定能不能接，基准是下面六条（细节见 `AGENTS.md`，这里是摘要）：

| 事实 | 位置 | 对扩容的含义 |
|---|---|---|
| Remotion 与 `@remotion/*` 全部精确 pin 在 **4.0.543**，React 19 | `template/package.json` | 新装的官方包必须同版本，不能 `^` |
| 效果统一签名 `(frame, fps, opts)`，组件不自己读 `useCurrentFrame` | `template/src/effects/index.ts` | 新效果照抄这个形状就能进样板间 |
| 动效全是纯函数（`ramp`/`enter`/`spring`/`keys`），伪随机走 `rand(seed)` 不用 `Math.random()` | `template/src/lib/anim.ts`、`effects/rand.ts` | 自带时钟、逐帧累加的库一律不能进 |
| 版式注册表 `LAYOUTS` 3 个 + `Missing` 红底兜底；`check_timing.py` 直接读 `Root.tsx` 的键集合，不维护第二份清单 | `template/src/Root.tsx:16`、`scripts-win/check_timing.py:109` | 新增版式不用改闸门；但 `onscreen` 新槽位要三处同步 |
| 4K 是 `zoom` 整块放大（布局按 1920×1080 写） | `template/src/Root.tsx` | **外部素材要按 1x 显示尺寸的 2 倍渲染**，否则 4K 出片会糊 |
| 十一道闸门 + `EffectsLab` 24 秒样板间（不走 timing.json） | `scripts-win/verify.ps1`、`template/src/scenes/EffectsLab.tsx` | 新效果必须先在样板间能过闸门 |

一句话：**这套东西的地基是"画面是时间的纯函数"**。扩容只有一个标准——别动地基。

## 2. 判定尺子：四问，答不上来就不接

1. **能不能只给一个 t 就得到那一帧？** 库里有没有 `seek(t)` / `Engine.update(delta)` / `f(t)` 这类外部驱动接口。
2. **第 N 帧能不能不模拟前 N-1 帧？** 渲染器并行抓帧，需要"从头积分"或"自带历史"的库会算出不确定的结果。
3. **它会不会自己抢时间？** `requestAnimationFrame` 主循环、`performance.now()`、CSS `transition/animation` 自己跑——有一个就算不合格（CSS 动画理论上可用 `animation-play-state` + `animation-delay` 同步，但等于放弃可维护性，本项目不采用）。
4. **这个镜头宣传片真的需要吗？** 第 4 问是防"20 个都接"的闸：能删掉而不影响观众理解的镜头，就不该做。

据此分四档：

| 档 | 含义 | 判定 | 本清单里的 |
|---|---|---|---|
| **A** | 有官方 `@remotion/*` 包，装完即用 | 内部已把库接到 frame 上 | Lottie、Rive、Three.js |
| **A-** | 天生纯函数，零封装 | `f(t) → 值` | Flubber |
| **B** | 有 seek 或固定步进，需自己包成 `frame → value` | 答得上第 1、2 问 | Anime.js、Matter.js、tsParticles（偏难）、Motion（未证实） |
| **C** | 独立引擎，渲成视频/图序列再嵌回 | 离线出图命令查实 | Manim、Blender、Godot、OpenToonz、Synfig、Inochi2D、Motion Canvas |
| **D** | 纯 CSS/DOM 或自带主循环且无公开 seek | 直接违反第 3 问 | AnimXYZ、mo.js、KUTE.js、React Spring |

## 4. 第一批：三件（合计约 1.5 人日）

### 4.1 Lottie：把"图标微动效"从手写变成素材

- **解决什么**：现在图标只会整体淡入淡出；UI 微交互特写（勾选、开关、加载环、箭头流转）手写 SVG 太贵。
- **怎么接**：`npm i @remotion/lottie@4.0.543 lottie-web@5.13.0`，JSON 放 `<项目>/public/lottie/*.json`，组件里 `<Lottie animationData={data} />`。
- **关键点**：`<Lottie>` 内部自己读 `useCurrentFrame`，与本项目"组件吃 frame"的约定冲突——**用 `<Sequence from={at}>` 包一层做偏移**，Sequence 会把帧号归零，约定即恢复，不用改 Lottie。
- **4K 优势**：矢量，放大 2 倍不糊，是本方案里唯一"零 4K 成本"的效果。
- **风险**：第三方 AE 模板的商用授权要跟素材一起记（见第 7 节）。

### 4.2 Flubber：形状 morph（最"显会做动画"的一招）

- **解决什么**：logo A→B、"旧流程的表格"变形为"新流程的看板"、图标切换的连续过渡。
- **怎么接**：`npm i flubber@0.4.2`，新建 `src/effects/Morph.tsx`，签名 `(frame, fps, { from, to, at, dur })`：

  ```tsx
  const interp = useMemo(() => interpolate(from, to), [from, to]); // 只建一次
  const t = ramp(frame, at, dur);                                  // 复用 anim.ts
  return <path d={interp(t)} fill={...} />;
  ```

- **关键点**：两条 path 要同坐标系、同方向；点数不同 flubber 会插值补齐；多个形状用 `interpolateAll`。渐变/描边走现有 `effects/LightSweep` 叠加即可。
- **成本**：2~3 小时，含形状预处理与锚点对齐。

### 4.3 Manim 离线通道（唯一需要动管道的一件）

- **解决什么**：公式逐行推导、坐标系/几何演示、算法流程推演——宣传片里"这东西怎么运作"的最高级的一段，Remotion 手写几乎做不出来。
- **链路**（新增 `scripts-win/render-offline.cmd` + `.ps1`）：

  ```
  项目/public/offline/<name>/frame_0000.png … frame_00NN.png
  项目/public/offline/<name>/meta.json
  ```

  `meta.json` 有 **14 个字段，由 `render-offline` 自动写，别手拼**（少一个字段闸门就判 ERROR）：`name`（片段名，须等于目录名）、`frames`（总帧数）、`fps`、`width`/`height`（出图像素尺寸）、`display_width`/`display_height`（这段在 1920×1080 布局里的显示尺寸；闸门按 `width ≥ display_width×2` **且** `height ≥ display_height×2` 逐帧判，两个方向都查；**倍率可调**：闸门 `--min-size-ratio`、渲染侧 `-MinRatio`，默认都是 2，两边要传一致，`--min-width-ratio` 是旧名仍可用但会提示改名）、`alpha`（true 时 PNG 必须是 colorType 4 或 6，写成 true 却输 RGBA 以外的格式会被判 ERROR）、`renderer`（可执行文件路径）、`command`（完整命令行，复现用）、`license`/`source`（授权与出处，闸门查非空）、`createdAt`、`generatedBy`。

- **入口只用 `.cmd`**：`scripts-win\render-offline.cmd <项目> <片段名> -Frames ...`。直接 `& .\render-offline.ps1` 会撞 ExecutionPolicy（默认 Restricted，实测 SecurityError），`.cmd` 里已带 `-ExecutionPolicy Bypass`。
- **`-Frames` 必填**：manim 是按场景时长出帧的，不写帧数时短渲染会静默变短、闸门还全绿；`render-offline` 拿它跟实际产帧数对账，少一帧就报错退出、不落目录。体积上限默认 600 MB（4K 两秒实测 240~480 MB 在阈值内）。**上游帧号不从 0000 起默认判失败**（渲染器自己的编号就是证据：说明它丢了开头几帧，静默重排会让内容整体前移、时间轴对不上）；确认渲染器只渲了中段才显式加 `-AllowShift`，那时才退化成 WARN + 重排。
- **渲染侧**：`manim -qh --format=png-sequence -t scene.py Scene`。这句是查过源码的（manim 0.22.1，`manim/cli/render/render_options.py`）：
  - `--format` 的取值是 `auto/none/png/png-sequence/gif/mp4/webm/mov`，帮助原文 *"PNG renders only the last frame; **png-sequence writes every rendered frame**"*——所以要逐帧 PNG 必须写 `png-sequence`，写 `png` 只会得到最后一帧。
  - `-t` 加 `--format=mp4` 会直接抛错，`manim/_config/output.py` 原文：*"MP4 output does not support an alpha channel. Use --format=mov or --format=webm for transparent video."*
  - PNG 序列比 `.mov`/`.webm` 稳：每帧一个文件，不依赖解码器与 seek（编码坑见 `docs/windows-踩坑记录.md`）。manim 自己的帧文件名不稳定，**由 `render-offline` 统一改名为 `frame_%04d.png`**，Remotion 侧不依赖上游命名。
- **环境成本（本机实测，别低估这一步）**：`manim` 与 `ffmpeg` 在这台机器上都**没装**（`Get-Command manim` / `ffmpeg` 均为空）；`MathTex` 还要 TeX Live（Windows 上按 GB 算）。建议第一批用**不依赖 LaTeX 的几何/流程图镜头**把通道验通，公式镜头等 TeX 环境装好再上——否则 1 人日会被环境安装吃掉大半。
- **Remotion 侧**：

  ```tsx
  <Sequence from={at} durationInFrames={n}>
    <Img src={staticFile(`offline/${name}/frame_${String(frame).padStart(4, "0")}.png`)} />
  </Sequence>
  ```

- **为什么不用带 alpha 的视频**：最终交付是 h264 mp4，alpha 本来就会在导出时被压平；透明只能靠 RGBA PNG 叠在场景底图上。所以**离线素材统一 PNG 序列 + 透明通道**，不引第二套视频解码路径。
- **体量与 4K 的硬账**（决定"离线镜头只能做局部"）：
  - 1080p RGBA PNG ≈ 1.5~3 MB/帧 → 2 秒 @30fps = 60 帧 ≈ **90~180 MB**；
  - 2160p ≈ 4~8 MB/帧 → 同样 2 秒 ≈ **240~480 MB**；
  - 而 4K 是 1x 布局 zoom 2 倍，**外渲素材要按 1x 显示尺寸的 2 倍出图**：局部元素在布局里占 900×500 px，就得渲 1800×1000。
  - 结论：**离线只做局部元素，全屏镜头不许走离线**，除非 ≤1 秒且确认仓库外挂。
- **不进 git 的只是帧**：`.gitignore` 按后缀忽略 `public/offline/**/*.png`，**`meta.json` 必须进 git**——`license`/`source` 的留痕只有它。把整个 `public/offline/` 忽略掉的话，别人克隆下来第 11 道闸门恒 SKIP、许可证审计只在你本机成立。帧是产物，靠 `render-offline` 一条命令重建。

## 6. 不接清单（写清为什么，避免下次重议）

| 工具 | 一句话理由 |
|---|---|
| AnimXYZ | 纯 CSS transition，违反"每帧由 frame 算出"，无补救；能力被 `enter()` 覆盖 |
| mo.js | 仅私有 `setProgress`，release 停 3 年，CoffeeScript 技术栈 |
| KUTE.js | 无文档化 seek、生态弱、与 `effects/` 重叠 |
| React Spring | 同功能已有纯函数弹簧；引入即两套口径 |
| Motion（Framer Motion） | 无 seek、官方 issue #399 仍未解决；布局/手势动画在宣传片里用不上 |
| Matter.js | 要"预积分存表"，本质离线；掉落堆叠用纯函数画更可控 |
| tsParticles | 自带 rAF，无 seek，只能改内部或自绘——那就不是它了 |
| Motion Canvas / Inochi2D / OpenToonz / Synfig | 只能离线，且 CLI 未查实；Manim 通道覆盖同类需求，需要时再按同一条链路补 |
| Godot | 同上（透明只有 PNG 序列），除非要做游戏化小剧场 |
| Remotion Skills | 不是渲染库，不进画面 |

## 11. 落地实测（2026-11-14，第一批 + 离线通道已进 `main`）

样板间现在是 8 段 / 720 帧 / 24 秒（`SEG_FRAMES=90`，`Root.tsx` 用 `durationInFrames={SEGMENTS.length * SEG_FRAMES}` 自算，加段不用回头改数字）。以下数字都是实跑出来的，不是估的。

**确定性（这是效果能不能进管线的第一道）**

- 同一个 headless-shell 158 里，frame 585 在 5 次独立渲染（2 次 still + 2 条不同 `--frames` 的 sequence + 单帧目录）md5 全等 `0f45f3b4f440dd6ae4f5e9ad743ac160`；frame 675 在 4 次渲染里全等 `a05661a50bb3da5110096376473d409d`；585 ≠ 586；180 帧序列 180 个唯一 md5。
- **但 Chrome 157 与 headless-shell 158 渲出来的 md5 不同**（同一帧像素级有差）。比确定性只能在同一个渲染器内比，跨渲染器比 md5 一定"失败"。
- `@remotion/lottie` 内部是 `<Sequence from>` + `useCurrentFrame`，而帧号换算里有 `Math.min(currentFrame, totalFrames-1)`（`utils.js`）——父级要是直接传全局帧（样板间第 7 段是 540~629），会**静默夹到最后一帧**，整段定格且不报错。正解是外层包 `<Freeze frame={...}>`：`Freeze.js` 把 timeline 帧设成 `frameToFreeze/playbackRate + relativeFrom` 并置 `cumulatedFrom: 0`，与 `useCurrentFrame` 的换算精确相消，冻结帧始终可见。
- `@remotion/lottie` 里 **1 个 Remotion 帧 = 1 个 lottie 帧**（走 `goToAndStop(..., true)` 帧模式 + `autoplay:false`），不按秒。所以素材的 `fr` 和组件层的 fps 要自己换算。

**段尾静止：`check_stills` 抓不到，得自己量**

- Lottie 段（540~629）中心 520×520 区域相邻帧差：运动段 median **2.0687**，尾段（585~629）只有 **0.0704**（29 倍差）；墨量 545 帧 27.0% → 565 帧峰值 35.96% → 585 帧起冻结在 23.266%。原因是素材的 keyframe 只到第 66 帧，段长 90 帧。
- Morph 段（630~719）极坐标 `r_max/r_min` 从 1.005（圆）→1.356（方）后，675 帧起不动；尾段 median 0.0827 vs 运动段 0.7814。
- 两段各 45 帧（1.5 秒）是死画面，而 `stills` / `check_stills` / `check_video` 全绿——它们每场景只抓 35% 与 85% 两帧、且只判"是不是几乎同图"。**素材规范要写死：Lottie 的动画必须铺满整段（`op` ≥ 段长且末个 keyframe 落在末帧附近）；morph 要回环或留后段变化，别让变形在段中段就结束。**

**已修（`2c22ecc`）**：素材整份重画成 8 个 shape layer（`disc` 静态圆底 + `check` trim 12→44 + `wave1..6` 起点错开 15 帧、各活 20 帧、末个 keyframe 95 被 `op=90` 裁掉），任意一帧都有波纹在动；`Morph` 新增 `pingPong`（三角波 `t = ease(clamp(1-|1-2·raw|))`，段里两实例改 `duration={3} pingPong`）。修后同一口径：Lottie 尾段/运动段 median **3.3679 / 3.4604 = 0.973**（修前 0.034），Morph **0.5680 / 0.5702 = 0.996**（修前 0.106），`< 0.05` 的帧对 **0/44**；585 vs 629、675 vs 715 的 md5 都不同了。**这条得能复量**，所以加了旁路工具 `scripts-win\check_motion.cmd <帧目录> [--segments "A=540-629,B=630-719"] [--region x0,y0,x1,y1]`（相邻帧平均像素差；尾段/运动段中位数比 < `--tail-ratio` 0.3 判 ERROR，单对 diff < `--identical` 0.05 判 WARN）。它**不**进 verify 的闸门计数——`check_stills` 每场景只比 35%/85% 两帧，天生抓不到段尾静止，这是审图时要顺手跑的第四只眼。

**2026-11-15 按三轮审查加固（`84a8b40`）**：`--segments` 只覆盖目录一部分时，漏掉的帧判 ERROR（确认只看这几段就加 `--allow-partial`，结果行写明覆盖多少帧）；段内取不到 ≥2 帧、或声明的范围里有帧号不在目录（没渲全）判 ERROR 并点名缺哪些帧；比值算不出来（运动段 median ≈ 0）**且**尾段 median < `--identical` 才判 ERROR——整段真静止先前会被「单点跳变」救成 exit 0；`--region` 写反/越界/非整数与目录里一张图都没有等参数环境错一律 `exit 2`（2 = 参数错，与「画面红」的 1 分开）；目录混了不属于主序列的带编号图判 ERROR（按「命名模式 + 像素尺寸」分组取最大组当主序列，不带编号的 `preview.png` 只 WARN 忽略）。「静止帧对 N/M」降为**信息行、不参与判定**：真实素材的片尾定版与极缓推镜会让它长期偏高，拿它判红只会逼人把阈值调成 0、把工具废掉。

**4K 锐度：用 `--scale=2` 验，别用 `Main4k`**

- `Main4k` 渲的是 `Video` + `timing.json`，**不含 EffectsLab**；Lottie/Morph 目前只被 EffectsLab 引用。要验效果在 4K 下糊不糊，直接 `npx remotion render src/index.ts Effects out/x --scale=2`。
- 结果：Lottie 图标区 `lap_abs` 4.3682 vs 1080p 双三次放大 2.1066 = **2.07×**，水平过渡 2px vs 5px；Morph 5.4675 vs 2.6643 = **2.05×**，1px vs 2px；非背景占比 0.989 / 1.002。矢量真按 4K 重画，不是放大。

**开销**

- 90 帧渲染：普通段 18.6s、Lottie 段 16.6s、Morph 段 17.2s；6 帧 6.5s vs 6.9s；4K still 6.4~7.0s vs 1080p 6.4s。接这两件没带来可见的渲染变慢。
- Morph 的 `maxSegmentLength` 要调：默认 10 太粗（棱角明显），调到 0.35 又让每帧 path `d` 膨胀到 37,323 字符、单帧 0.228ms（默认 10 是 1,149 字符 / 0.007ms，33 倍）。收尾定在 **0.9**：`d` 18,241 字符（最多 18,691）、`f(t)` 0.27ms、建插值器 15ms；520px 画面上 0.9 个 viewBox 单位约 4.7px 弦长、弓高 < 0.02px，肉眼无差。
- 整条样板间 `npm run render:effects`：720/720 帧、`out/effects.mp4` 6.84 MB、含编码 **47.98s**；ffprobe h264 / 1920×1080 / 30fps / duration 24.000000；`check_video.py --duration 24` 0 ERROR / 0 WARN；按段中点抽 8 帧 md5 全不同、`#2a0d0d`（Missing 红底）占比全 0.0000。
