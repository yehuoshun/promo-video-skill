# 复盘抗删方案：mp4 可以删，事实不能丢

- **起因**：`examples/self-promo` 交付后，把 `out/`（含两支成片、11 张静帧、`verify-log.jsonl`）整目录删掉，再跑 `retro.cmd`，复盘不是变空，而是**写出与事实相反的结论**——静帧判「✗ 没截图」、闸门历史写「这个工程还没跑过」、发布写「还没发」。
- **要回答的问题**：一支片交付之后，哪些事实必须脱离 `out/` 活下来？活下来的形态是什么（文件、位置、字段）？谁在什么时候写？写错了（源变了、版本又改了）怎么发现？
- **数据来源**：三条实测——① 复制 `self-promo` 去掉 `out/` 跑 `retro.py --stdout` 的逐行输出；② `scripts-win/retro.py` 源码（行号见文内）；③ 工程内 `.gitignore` 与实际产物体积。文中每个数字都是当场数出来的，没有一项按印象写。

## 0. 结论先行

1. **成片是可重建的派生产物，不是档案。** `timing.json` + `src/` + `public/` + `package-lock.json` 全在 git 里，重渲一条 `npm run render`。一支 40.8 MB + 47.2 MB 的双版本进 git 既超 GitHub 单文件 100 MB 红线，又让仓库体积一次涨近 90 MB——**mp4 不进 git 这个判断不需要再讨论**（`.gitignore:12` 已经这么写了）。
2. **不能只写一份给人看的 md。** 复盘的下游是脚本（重算红线、数闸门历史、判断「从没真跑过的闸门」），人看的表格机器读不了。做法是**一份 md 里嵌一段机器可读快照**：人读上面的表，`retro.py` 读下面的 `<!-- delivery:json ... -->`，两者由同一个写入点生成，不会互相漂移。
3. **不新造文件，把 `复盘.md` 改成「交付时写一次、之后只追加」。** [retro.py:495](scripts-win/retro.py) 早就写着「本文件只增不改」，但 [retro.py:737](scripts-win/retro.py) 每次都整篇覆盖——这条承诺现在只有三个人工答案真的被保住了（[retro.py:480](scripts-win/retro.py)）。快照写进事实区，正好让这句话变成真的。
4. **缺产物要说「不知道」，不许说「没做」。** 现在三处都是把「文件不在」渲染成结论：[retro.py:426](scripts-win/retro.py) 的 `✗ 没截图`、[retro.py:474](scripts-win/retro.py) 的「这个工程还没跑过」、发布行的「还没发」。这类文案比空着更糟：它让人以为闸门拦过、人看过。
5. **产物一律出仓库，落工作区 `data/`。** 成片、静帧、`sheet.jpg`、三张平台封面，以及要拿去分析的那份 md，全部放 `<工作区>/data/promo-video-skill/<片子标题>/`，命名用片子标题（如 `不装剪辑软件，写清需求它自己出片.md`）——不进 git、不上传。仓库里只留几十 KB 的文本事实（`复盘.md` + `delivery:json`）。物证仍要留：`sheet.jpg` 是「这一版长什么样」的唯一证据，只是不留成片在仓库里。

## 1. 现状：删掉 out/ 以后，复盘会说什么

演练方法：`robocopy` 把 `examples/self-promo` 复制一份，只保留 `timing.json`、`publish.json`、`public/`（**不带 `out/`、不带 `publish.local.json`**），跑 `python scripts-win\retro.py -Project <副本> --stdout`，与工程里已提交的 `复盘.md` 逐行对比：

| 事实 | 真实情况 | 删掉 out/ 后的复盘 | 代码位置 |
|---|---|---|---|
| 成片 / 交付件 | 4 行：40.8 MB / 52.80s / 6.2 Mbps / 1920×1080，以及竖版 47.2 MB / 7.2 Mbps / 1080×1920 | **整段消失** | [retro.py:156-168](scripts-win/retro.py) 只认 `out/*.mp4` 与工程根 `*.mp4` |
| 静帧 | `out/stills` 11 张 + `out/sheet.jpg` | `out/stills 是空的`，红线第 1 条判 **`✗ 没截图`** | [retro.py:194-197](scripts-win/retro.py)、[retro.py:426](scripts-win/retro.py) |
| 闸门历史 | 1 轮：6 通过 / 2 警告 / 0 失败 / 2 跳过；从没真跑过：排版、离线素材 | 「没找到 `out/verify-log.jsonl`（…这个工程还没跑过，或用过 -NoLog）」——**假陈述** | [retro.py:203-239](scripts-win/retro.py)、[retro.py:474](scripts-win/retro.py) |
| 发布 | B站 已发布 | 「还没发」 | `publish.local.json` 是本机文件（`.gitignore` 挡住），副本里没有 |
| 覆盖风险 | 已提交的复盘是唯一档案 | 重跑一次就把档案**永久改成**上面那些假事实 | [retro.py:737](scripts-win/retro.py) 无条件 `write_text`，CLI（[retro.py:705-714](scripts-win/retro.py)）没有 `--force` |

**这不是「归档没做好」，是「判断依据错了」。** 用户在手机上看到「✗ 没截图」会以为自己当时跳过了审图，而实际上审图做了、11 张静帧也看过——只是文件后来被删了。

## 2. 根因：事实分三类，只有一类在 out/ 里

| 类 | 内容 | 现在在哪 | 能不能重算 |
|---|---|---|---|
| **A 源** | `timing.json`、`src/scenes/*`、`public/` 素材、`package-lock.json`、`publish.json`、git log | git | 是（真正的唯一真相） |
| **B 产物** | 成片 mp4、`out/stills/`、`out/sheet.jpg`、`out/verify-log.jsonl` | `out/`，被忽略 | **不能**——重渲出来的是「新的一版」，不是当时那一版 |
| **C 本机个人数据** | `publish.local.json`（链接/时刻/播放数）、`发布记录.local.md` | 工程根，被忽略 | 不能，也不该进仓库 |

现在的事实区把 A、B、C 混在一张表里，**读的是 B 的文件是否存在**，于是 B 一删就等于事实归零。方案要做的事只有一件：**在 B 还存在的那一刻，把 B 里对复盘有用的部分固化成 A 形态（进 git 的文本），之后复盘的读取路径只走 git 文件。**

## 3. 设计：一份 md 装三类事实

`复盘.md` 从「每次重算的报告」变成「**一支片的档案**」，结构固定为五段：

```
# 复盘：<工程名>
> 生成：<时间> · `scripts-win\retro.cmd -Project . -Snapshot`（快照指纹见文末，别手改这一段）

## 一、片子            ← 交付时一次写入（本机产物在时顺手校验字节/sha）
## 二、施工            ← 交付时一次写入（闸门历史、提交、返工）
## 三、只有人知道的     ← 三个问题，人工填，永不覆盖
## 四、账本            ← 指向 docs/错误清单.md，只增不改
## 五、发布            ← 交付后只追加：平台名（不含链接与时刻）
<!-- delivery:json {…} -->   ← 一行 JSON，机器只读这里
```

生命周期（一支片只经历三次写入）：

| 时机 | 命令 | 写什么 | 判据 |
|---|---|---|---|
| 阶段 9 交付（`verify` 全绿） | `retro.cmd -Project . -Snapshot` | 一次性写全：事实区 + 嵌 JSON + 三问空位 | `verify.cmd` exit 0 且 `out/stills` 非空 |
| 阶段 10 发布后 | `retro.cmd -Project . -Published <平台名>` | 只在「五、发布」追加一行 | `publish.json` 里该平台的条目存在 |
| 阶段 11 改版前 | `retro.cmd -Project .`（默认） | **只读快照**，缺什么标什么；不动事实区 | 见 §5 |

**产物去向：** `-Snapshot` 默认同时把成片、静帧、`sheet.jpg`、三张封面拷进 `<工作区>/data/promo-video-skill/<片子标题>/`（`-Keep off` 关掉），仓库里不新增任何二进制。

**为什么是 md 而不是 json：** 用户要的是「生成完一个视频后写一份 md 用于后面分析」——分析的主体是人（看返工、看闸门、看素材够不够）。json 只是让脚本还能参与同一份文件；如果把事实拆进第二个文件，就会出现「md 说 40.8 MB、json 说 40.7 MB」这种同步成本，而这类成本在这个仓库里已经付过一次（`publish.json` 与本机覆盖层）。

## 4. 数据契约：`delivery:json` 字段表

写在 md 末尾，**单行、键序固定**（diff 才好看），`schema` 版本号用于以后加字段：

```json
{"schema":1,"project":"self-promo","snapshotAt":"2026-11-17T23:41+08:00","commit":"544c128",
 "duration":52.8,"fps":60,"frames":3168,"canvas":"1920x1080",
 "scenes":{"total":5,"byType":{"info":2,"hook":1,"showcase":1,"cta":1}},
 "inputs":{"timingSha1":"…","lockSha1":"…","publicFiles":7,"publicBytes":…,"bgm":"bgm.wav"},
 "renders":[{"name":"宣传片 1080p60 横版.mp4","bytes":40792508,"sha256_16":"8f3a…","duration":52.8,"fps":60,"width":1920,"height":1080,"bitrateMbps":6.2,"renderedAt":"2026-11-17T22:9+08:00"}],
 "stills":{"count":11,"sheet":true,"sheetBytes":889000},
 "verify":{"runs":1,"last":{"at":"2026-11-17T22:57","pass":6,"warn":2,"fail":0,"skip":2},
           "gates":{"check_stills":"PASS","check_offline":"SKIP","…":"…"},
           "neverRan":["排版","离线素材"]},
 "voice":{"lines":0,"sfx":6}}
```

| 字段 | 来源 | 缺了怎么办 |
|---|---|---|
| `duration`/`fps`/`canvas`/`scenes` | `timing.json`（A） | 不可能缺；缺了直接 exit 2 |
| `inputs.*` | 当场对 `timing.json`、`package-lock.json`、`public/` 算 sha1 / 文件数（A） | 同上 |
| `renders[]` | 交付件 mp4 的 `os.stat` + `ffprobe`/`read_duration`（B） | 本机没有就不写这项，表里标「本机无成片，按交付时记录 40.8 MB / 52.80s」 |
| `stills` | `out/stills` 与 `out/sheet.jpg`（B） | 同上，标「本机无静帧」而不是「没截图」 |
| `verify.*` | `out/verify-log.jsonl`（B） | 本机没有就只留 `runs`/`neverRan` 之外的历史结论，标「本机无 verify-log」 |
| `commit` | 快照写入时的 `git rev-parse --short HEAD` | 非 git 目录写 `null` |

**隐私红线（与 `AGENTS.md` 的阶段 10 同一条）：** 快照里**不得**出现发布链接、发布时刻、账号、播放数据。平台名可以（「B站」「语雀」），链接与时刻只留在 `publish.local.json`。写完后用下面这条自查，必须 0 命中：

```powershell
Select-String -Path 复盘.md -Pattern 'bilibili\.com|BV[0-9A-Za-z]{10}|yuque\.com/https?://|t=[0-9]{4}-'
```

**体积与位置：** 快照 JSON 约 1.5 KB、`复盘.md` 全文约 6 KB——这是仓库唯一增加的部分（一年 6 支片约 36 KB）。成片、静帧、`sheet.jpg`、封面、以及分析用的 md 全部出仓库，落工作区 `data/promo-video-skill/<片子标题>/`（含成片约 90 MB、不含约 1.8 MB），不进 git。`delivery:json` 里只记文件名与 `sha256_16`，**不记绝对路径**——路径是本机事实，换台机器就不成立了。

## 5. `retro.py` 改造点

**读取顺序（默认模式，无参数）：**

1. 有 `复盘.md` 的 `delivery:json` → 用它填事实区，**不扫 `out/`**；本机产物存在时顺手校验（字节 / sha256 前 16 位 / 时长），不一致就写一行「本机文件与快照不符（交付 40.8 MB，本机 39.1 MB）」，不静默。
2. 没有快照 → 退回现在的扫描行为，但**缺失语义全部改掉**：不写 `✗ 没截图`、不写「还没跑过」、不写「还没发」，统一写「本机产物已删 / 台账无记录」并在一级标题下给一句 WARN。
3. 本机产物缺、台账也无、且已有 `复盘.md` → **拒绝覆盖并 exit 3**（`--force` 才写），保证旧档案不会被一次误跑改成假事实。

**新增 CLI 参数：**

| 参数 | 作用 |
|---|---|
| `-Snapshot` / `--snapshot` | 交付时写档案：事实区 + 嵌 JSON + 三问空位；本机 `out/` 必须在，静帧为空则 exit 4（没有审图就没有交付） |
| `-Published <平台>` / `--published` | 只追加「五、发布」一行平台名；快照里没有该平台 → exit 5 |
| `--rebuild` | 回到现在的「扫 out/ 重算」行为，用于快照写错时抢救；要求本机产物在，否则 exit 3 |
| `--force` | 允许覆盖已有档案（默认禁止） |

**「快照未刷新」检测：** 读快照里的 `inputs.timingSha1`、`inputs.lockSha1`、`inputs.publicFiles`，与当前文件重算对比；任一不同 → 在事实区顶部写一行 `⚠ 快照落后于源：timing.json 已变（快照 sha1 a1b2…，当前 c3d4…），重跑 -Snapshot 或 -rebuild`，**不自动改写**。这条是防止「交付后偷偷改片、档案还停在旧版」——[retro.py:480](scripts-win/retro.py) 保住的三个人工答案不能成为唯一的不一致检测手段。

## 6. 写入点与闸门

- **阶段 9 出口**：`verify.cmd` 全绿后，人跑 `retro.cmd -Project . -Snapshot`（`verify.ps1` 末尾提示这一行，不改 `verify` 的退出码）。
- **阶段 10 出口**：`check_publish.py` 只管文案；平台名由 `retro.cmd -Published` 追加。
- **阶段 11 出口**：`AGENTS.md` 现有的「`复盘.md` 已写（`retro.cmd -Project .`）」保留，含义变成「档案已存在且快照未过期」。
- **`verify` 不加新闸门**：快照是档案问题，不是画面问题；混进 11 道闸门会让「闸门数量」这个对外说法失真（见 `AGENTS.md` 开头那段说明）。

## 7. 留档：`data/` 里存一份「这一版长什么样」

产物与物证一律出仓库，落工作区 `data/`（不在任何 git 仓库里）：

```
<工作区>/data/promo-video-skill/
  不装剪辑软件，写清需求它自己出片/        ← 目录名 = 片子标题
    不装剪辑软件，写清需求它自己出片.md     ← 分析台账（含发布数据，故不进 git）
    成片-横版.mp4 / 成片-竖版.mp4          ← 原样拷，不重编码
    sheet.jpg                              ← 11 帧拼图，889 KB
    封面-横版.jpg / 封面-竖版.jpg / 封面-3by4.jpg
```

- **触发**：`retro.cmd -Snapshot` 写 `复盘.md` 的同时，默认把这几样从 `out/` 拷进上面这个目录（`-Keep off` 关）。之后 `out/` 被删、换机器，留档都还在。
- **不进 git 的两条理由**：公开仓库不放大二进制；分析台账里迟早要写播放量、评论、涨粉——那是个人数据，`AGENTS.md` 阶段 10 的红线本来就不许进仓库。
- **仓库侧只留文本**：`复盘.md` 的表与 `delivery:json` 记文件名 + `sha256_16`，不记绝对路径；缺了图也能知道「当初留过哪几张、哪一版」。
- **两份 md 的关系**：仓库 `复盘.md` = 公开事实（到此为止）；`data/…/<片子标题>.md` = 同一份公开事实 + 「六、数据」（播放量/评论/涨粉，只在本机填）。两份都由 `-Snapshot` 从同一个函数生成，公开部分不会漂移；以后要加字段，两边一起变。
- **不再需要 `archive-delivery.cmd`**：留档就是交付动作的一部分，不另造一套手动流程。

## 9. 迁移：把 self-promo 的现状固化成第一份档案

`examples/self-promo/out/` 现在还在（40.8 MB + 47.2 MB 成片、11 张静帧、1 轮 verify 日志）。**赶在它被删之前**跑一次 `retro.cmd -Project . -Snapshot --force`，生成的 `复盘.md` 就成了这一版的第一份档案；之后删 `out/` 不再是事故。快照写完后按 §8 第 1、2 条各验一次，再提交。

## 10. 明确不做

- **mp4 进 git**（体积、单文件上限、且可重建）。
- **把 `timing.json` 的事实搬进快照当唯一真相**：快照只是它在某一刻的读数，改片还得改 `timing.json`。
- **自动同步语雀**：`-Yuque` 仍是显式开关，默认不碰网络（现有行为不变）。
- **在 `verify` 里加快照闸门**：理由见 §6。
